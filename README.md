# 百度输入法 Mod 模块

**1.4.0 新增“取消九键用户词的时间扣分”独立开关，默认关闭。** 开启后仅在九键拼音的当前内核调用中，将三条用户词评分路径的词龄按零计算；词频学习、频次折半和旧词淘汰仍执行原规则。保留已选拼音逐个撤销及候选刷新、绿色拼音、剪贴板抢救、可调候选栏起滑阈值、跟手滚动和惯性。面向 Android 15（SDK 35）、LSPosed modern API 100，作用域为 `com.baidu.input`；新增 native 功能仅适配已核对的 ARM64 内核。

所有功能都不再使用整类替换：已删除 20 个 smali 覆盖类、DEX 前置加载器、资源表覆盖器和 smali 汇编任务。模块不会改动应用 ClassLoader、`dexElements`、安装 APK 或应用签名。构建编译模块、API 100 设置通信源码和 JNI 评分 Hook，使用固定版本 ShadowHook 2.0.1。

九键拼音输入 `2253`，依次选择 `ba`、`ke` 后，第一次删除撤销 `ke`，第二次撤销 `ba`；两次都保留输入字符，之后再按删除才进入原版字符删除逻辑。适用于一个或多个已选拼音，按选择顺序的逆序撤销。已选拼音显示为绿色 `#00C853`，未选拼音和汉字保留原有颜色。此行为默认启用，独立于顶部候选栏滚动开关。实现及适配依据见 [拼音选择说明](docs/pinyin-selection.md)。

## 设置与安装

1. 安装 Actions 生成的模块 APK，在 LSPosed 中启用，作用域勾选百度输入法。
2. **首次安装或升级模块后，强行停止百度输入法所有进程再打开，或重启设备。** 已运行进程无法自行卸载旧版本的整类覆盖。
3. 打开模块的设置界面，调整“顶部候选栏跟手滚动”、横向滑动起始阈值、惯性强度和减速时长。跟手滚动默认开启，关闭后使用输入法原有触摸行为。未连接 LSPosed 时设置不可操作；保存失败时恢复上次的控件值并提示。
4. 设置通过 LSPosed API 100 的远程 preferences 保存。滑块松手后自动保存，滚动参数从下一次手势生效，进行中的触摸仍完成清理。关闭跟手滚动会停止正在进行的惯性。“取消九键用户词的时间扣分”独立保存，从下一次输入或候选刷新生效。
5. **剪贴板抢救**：升级后先重新启动输入法，只调出键盘，不打开剪贴板；进入模块界面顶部的“剪贴板抢救”，点击“移除最新一条剪贴板内容”并确认。输入法后台按更新时间选取历史/最近使用列表中的最新内容，移除该内容及另一列表中的相同内容副本；包括最新内容已被置顶的情况。界面显示实际处理结果，成功后输入法进程退出以释放旧缓存，再次调出键盘即可。若系统剪贴板仍保留原超长文本，请先复制一段短文本，避免再次入库。无需额外 Root 授权。详情见 [剪贴板抢救说明](docs/clipboard-rescue.md)。
6. **取消九键用户词的时间扣分**：在设置页启用同名开关。默认关闭，关闭时评分参数原样传入；不改写用户词库、不修改学习时间、不阻止折半或淘汰，也不保证固定首选。只支持百度输入法 **13.3.6.52（1149）** 已核对的 `arm64-v8a/libiptcore.so`，不匹配时禁用该功能并记录日志，其他功能独立加载。细节见 [九键用户词时间评分说明](docs/nine-key-memory.md)。

这项开关仅控制九键模式的**顶部横向汉字候选栏**：按住时左右跟手移动，松手后逐渐减速滑行，到边界停止，再次触摸打断惯性，保留横向拖动防误选。横向位移超过所设起始阈值且大于纵向位移时才起滑；点击时的轻微抖动和上下移动保留原候选，未触发横向拖动时松手沿用按下的位置。左侧拼音列表使用百度原版行为。其他 Mod 功能保持启用。

横向滑动起始阈值可设置为系统点击容差的 **0%–300%**，默认 **100%**，保持 1.3.3 的起滑距离。页面同时显示对应像素数；调小更容易起滑，调大可容忍更多点击抖动，0% 最灵敏。“恢复默认起始阈值”只重置这个参数。滑块松手后自动保存，下一次候选栏触摸生效。

| 惯性参数 | 范围 | 默认 | 效果 |
| --- | --- | --- | --- |
| 惯性强度 | 0%–200% | 60% | 调整松手初速度，越大滑得越远；0% 为松手即停 |
| 减速时长 | 100–1500 毫秒，步进 50 毫秒 | 450 毫秒 | 越大减速越缓、滑行越久；到边界提前停止 |

设置页提供“恢复默认惯性”按钮。慢速拖动、停住后松手、取消触摸及多指手势不会启动惯性。

## 功能与 Hook 范围

| 功能 | 当前实现 |
| --- | --- |
| 九键用户词时间扣分 | 独立开关默认关闭；在实际 Java → native 内核调用线程判断九键拼音状态，以可嵌套 TLS 限定范围；三条原版用户词评分函数只替换本次的时间参数，保留原拼音匹配、频次及其他评分修正；安装前校验文件哈希及运行中完整函数指令 |
| 剪贴板容量 | 调整配置返回值、配置写入参数及剪贴板查询的数量限制到 100000000；保留原协程和数据库操作 |
| 剪贴板文本 | 仅在剪贴板处理与编辑调用期间提高 LengthFilter 上限；同步超限检查使用过滤后的临时查询结果，不修改数据库对象 |
| 剪贴板抢救 | 模块 UI 发送有序广播，由输入法进程后台直接对剪贴板数据库执行事务删除；只查询记录编号和排序元数据，不将超长正文读入界面；成功后回传结果并退出输入法进程以清除缓存 |
| 常用语编辑 | 提高指定编辑流程的 LengthFilter 和字数提示上限到 100000000 |
| 编辑菜单 | 在原菜单布局方法读取数组之前调整目标数组顺序，保留原布局及点击命中计算 |
| 标签布局 | 隐藏 ID 2；ID 0、1 增加 16dp 宽度并取消左右间距；未选中标题宽度上限提高到 150dp；保留常用语标题空格 |
| 颜色透明度 | 在原调色方法的调用范围内调整透明度参数，保留皮肤与日夜模式计算；修改两个剪贴板分隔线的背景透明度 |
| 四条资源文案 | 按资源名称处理 Resources / TypedArray 的字符串读取；无需完整资源表或固定数值 ID |
| 顶部候选栏 | Hook `CandidateView.onTouchEvent(MotionEvent)`、`r0()` 及继承的 `AbsSoftView.dispatchTouchEvent(MotionEvent)`；分发 Hook 只为已捕获的顶部手势提前进入低阈值移动分支，保留原坐标更新和抬手清理；拖动和惯性调用原候选布局 |
| 九键拼音删除 | 在内核线程的删键入口读取最新选择状态，通过原版 `actInputCursor`、`actInputPop` 撤销最后一个已选拼音；光标使用独立回调对象，撤销后同步更新输入串、汉字候选和拼音候选；全部撤销后沿用原版字符删除 |
| 已选拼音颜色 | 在普通及内嵌拼音栏的绘制范围内，覆盖普通和硬件加速 Canvas 的文字绘制入口，把已选拼音改为绿色；反优化绘制辅助方法，保留原画笔透明度，混合文本中的汉字维持原色 |

迁移依据及旧功能逐项对应见 [方法 Hook 迁移说明](docs/hook-migration.md)。候选栏手势细节见 [候选栏说明](docs/candidate-scroll.md)。

## 兼容策略

- 不再以整张资源表 SHA-256 作为全模块加载条件。各功能独立安装，安装失败回滚该组已注册的 Hook，并在日志中说明原因。
- 方法按类名、方法名、参数和返回类型解析；关键字段检查类型。每个手势的状态放在模块自己的弱引用映射中，不给百度原类增加字段。
- 使用系统方法的 Hook 只在指定百度方法的本次调用范围内调整参数；线程上下文在返回或异常时恢复。已知可能内联的调用点采用 API 100 的定点反优化。
- 用户词评分 Hook 只支持已验证的 ARM64 库 SHA-256。功能首次启用且进入九键内核调用时才加载 JNI 并安装；三个评分点必须全部安装成功才允许覆盖时间，失败时保留原评分。设置切换只改变调用范围，不反复改写或撤销 native 跳板。
- 适配依据仍是用户提供的百度输入法 **13.3.6.52（1149）** 源材料。改用 Hook 降低了对完整类实现和资源表的耦合，**不保证未来任意版本自动兼容**：若混淆名、字段或语义改变，仍需更新对应适配。

日志以 `Hook group installed:`、`Hook group unavailable; keeping app behavior:` 区分各功能安装结果；调用时发现不兼容会输出 `Hook disabled after incompatible call:`。候选栏额外输出最多四十八条不含候选内容的 `CandidateScroll 1.3.4` 日志，包括触摸入口的开关/九键状态、顶部 DOWN 捕获结果、`early MOVE enabled`、拖动与普通点击释放结果、相对横纵位移及实际起始阈值、阈值百分比、惯性启动参数。惯性适配异常单独输出 `Candidate inertia disabled; direct touch scrolling remains enabled`，不停止已安装的跟手拖动 Hook。安装日志仅表示 Hook 注册完成，不能代替设备效果验证。

## GitHub Actions 构建

推送到 `main` 自动触发 [Build APK](.github/workflows/build-apk.yml)，也支持手动触发。流水线使用 JDK 17、Gradle 8.9、Android SDK 35、AGP 8.7.3、NDK 27.2.12479018 和 CMake 3.22.1。SDK 初始化显式安装 platform-tools，随后安装平台、Build Tools、NDK 和 CMake。APK 保留未压缩的 ARM64 native 库，供 LSPosed 模块 ClassLoader 直接加载；JNI 与依赖库按 16 KiB 内存页对齐。编译命令：

```sh
gradle --no-daemon --console=plain :app:assembleRelease
```

下载 `baiduinput-mod-api100-<commit>` artifact，解压得到 `app-release.apk`。产物使用 CI debug keystore 签名，可直接安装，不需要仓库 secrets。密钥由 Actions cache 保存；缓存丢失产生新密钥时需卸载旧模块后安装。

API 接口以 `compileOnly` 依赖引用。API 100 的官方设置服务 Java / AIDL 源码固定在 `xposed-service` 中，避免依赖 Maven Central 当前仅发布的 101 / 102 版本。来源与许可见 [第三方材料](THIRD_PARTY_NOTICES.md)。

按用户要求，本次不运行测试、本地 Gradle 或设备验证，推送后只确认工作流启动，不等待构建结束。
